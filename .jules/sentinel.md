## 2024-05-24 - Information Leakage in VPN Error Reporting
**Vulnerability:** The `VpnError` class was capturing full stack traces via `Throwable.stackTraceToString()` and including them in the `details` field. Additionally, error messages were not sanitized, potentially exposing sensitive information like NordVPN service credentials (usernames/passwords) if they were present in exception messages.
**Learning:** Defaulting to full stack trace capture in error objects intended for UI display or broad logging creates a significant information leakage risk. In this codebase, VPN authentication failures often include credential-related strings in the exception message, which were then propagated to the UI.
**Prevention:** Always use `Throwable.toString()` instead of `stackTraceToString()` for production error details. Implement a centralized sanitization factory (like `VpnError.create`) that applies Regex-based redaction for known sensitive keywords (password, token, secret, etc.) before the error object is instantiated.
