## 2026-07-05 - Global Cleartext Prohibited & Info Leakage Mitigation
**Vulnerability:** The application allowed global cleartext traffic (`android:usesCleartextTraffic="true"`) and had specific domain exceptions for `ip-api.com`, which does not support HTTPS on its free tier. Additionally, VPN error messages leaked stack traces to the user (CWE-209).
**Learning:** Legacy testing requirements (like GeoIP lookups during VPN development) often lead to overly permissive network security configurations that persist into production-ready code. Relying on API providers that don't support HTTPS for free tiers creates a structural pressure to allow insecure traffic. Additionally, hardening production manifests can break E2E tests (e.g., Maestro) that rely on cleartext traffic for local mock servers or browser-based verification.
**Prevention:** Always use GeoIP providers that support HTTPS (e.g., freeipapi.com). Enforce `android:usesCleartextTraffic="false"` and `android:allowBackup="false"` as baseline security defaults. Wrap error message generation to explicitly exclude internal `details` or stack trace fields. For E2E testing, use a dedicated debug manifest with `tools:replace` to safely re-enable cleartext traffic and backups only for test environments.
