## 2026-03-02 - Plaintext Credential Exposure via Temporary Auth Files on Disk
**Vulnerability:** plain-text OpenVPN authentication credentials (username and password) were written to the device's local cache directory (`context.cacheDir`) to pass credentials to the native OpenVPN layer, but they were never cleaned up. This resulted in user credentials permanently residing on the local filesystem.
**Learning:** The native OpenVPN 3 ClientAPI's `provide_creds` utilizes memory strings rather than file-based credential lookup, making the temporary files redundant after initial parsing in the JVM layer. Even when temporary credentials must be written to disk for legacy reasons, they should be cleaned up immediately once they are read into memory.
**Prevention:** Always wrap temporary file usage in a `try-finally` block and delete the files eagerly in the `finally` block. Ensure the files are created with owner-only POSIX permissions (`setReadable(true, true)` and `setWritable(true, true)`) to prevent local privilege escalation.
