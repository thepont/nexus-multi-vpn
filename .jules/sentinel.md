## 2025-11-17 - Insecure Cleartext Geolocation Lookup and Production Manifest Overrides
**Vulnerability:** The application used insecure cleartext HTTP (`http://ip-api.com/`) for geographical region detection. Plaintext HTTP traffic is vulnerable to Man-in-the-Middle (MitM) routing-spoofing and traffic manipulation. In addition, `android:usesCleartextTraffic` and `android:allowBackup` were globally enabled in the production `AndroidManifest.xml` and `network_security_config.xml`.

**Learning:** Migrating to HTTPS for GeoIP services (e.g., `https://free.freeipapi.com/api/`) required mapping response fields correctly across both production Gson parsing (`GeoIpService.kt`) and test Moshi parsing (`IpCheckService.kt`). Hardening the production build requires disabling cleartext traffic globally, but doing so would break local E2E/mock server testing. Therefore, we had to implement highly target-specific debug Manifest overrides (`tools:replace="android:allowBackup,android:usesCleartextTraffic"`) in the debug manifest (`app/src/debug/AndroidManifest.xml`) rather than blanket main manifest rules.

**Prevention:** Always prioritize secure HTTPS endpoints for third-party metadata lookups. Use selective build-type (e.g., `debug`) overrides with explicit `tools:replace` XML directives when non-production network configurations are required for local testing or CI pipelines, keeping the production manifest completely hardened by default.
